# Process Decomposition Methodology

> 版本: v0.1.0 | 适用范围: P4/P5/P6 设计与评审

## 1. 目标与适用范围

1. 为流程拆分提供执行级方法论标准，避免“语义重叠、职责漂移、可复用边界不清”。
2. 适用于所有新增或重构流程，尤其是 `bundle -> P5` 迁移场景。
3. 本标准与 `docs/design/standards/process-definition-standard.md` 联动使用；任一冲突按 Fail-Closed 处理。

## 2. 拆分流程（先结论后展开，分组递进）

### 2.1 结论层（先回答“怎么拆”）

1. 先给出目标流程树：P4 编排层、P5 复用层、P6 原子执行层。
2. 先确定“哪些语义不能合并”：高风险 AP 语义边界、生命周期断点、发布/治理动作。
3. 输出首版迁移结论：旧节点退役列表、目标 P5 子流程列表、调用方迁移顺序。

### 2.2 分组层（解释“为什么这样拆”）

1. 按业务义务分组：Objective/Spec/Test/Implement/Verify/Lifecycle/Release/Evolution。
2. 按生命周期连续段分组：开发前准备、实现断点、开发后评测、治理收口。
3. 按复用画像分组：normal/refactor/hotfix 等 profile。

### 2.3 证据层（证明“拆分可执行”）

1. 每个候选子流程必须给出输入契约、输出契约、调用方、失败回退策略。
2. 每个重叠点必须给出“解释 + 解耦路径”。
3. 无证据项视为不可实施，直接阻断进入实现阶段。

## 3. MECE 划分规则与反例

### 3.1 MECE 规则

1. 职责互斥（Mutually Exclusive）：同一 AP 语义只允许一个主责任子流程承载。
2. 覆盖完整（Collectively Exhaustive）：从输入到输出链路必须全覆盖，不能留下无主职责。
3. 若同一 AP 在多个流程出现，必须通过 profile 或调用方边界进行语义隔离。

### 3.2 反例（禁止）

1. 同一子流程同时承担“需求归一 + 规格编排 + 发布打包”。
2. 多个子流程重复声明同一个输出契约主语义（例如多个流程都声明自己产出唯一 `spec_ref`）。
3. 以历史 bundle 编号拼接命名替代语义命名，导致责任边界无法理解。

## 4. 金字塔表达模板（结论层 / 分组层 / 证据层）

### 4.1 结论层模板

1. 结论：`<旧节点>` 退役，替换为 `<目标 P5 ID>`。
2. 影响：调用方 `<流程.phase>`。
3. 顺序：迁移序号 `<N>`。

### 4.2 分组层模板

1. 分组依据：业务义务组 / 生命周期组 / profile 组。
2. 该组边界：输入约束、输出约束、禁止越界行为。

### 4.3 证据层模板

1. 输入契约：`required[]`。
2. 输出契约：`required[]`。
3. Fail-Closed：失败触发条件与回退路径。
4. 重叠解释：若有一对多/多对多映射，必须附解耦说明。

## 5. SRP / DIP / LoD / 组合复用判定规则

### 5.1 SRP（单一职责）

1. 子流程只对一类治理结果负责。
2. 若一个子流程需要解释超过一种独立治理结果，必须拆分。

### 5.2 DIP（依赖倒置）

1. 父流程只能依赖子流程契约（I/O + fail policy）。
2. 父流程不得依赖子流程内部脚本、临时文件或实现细节。

### 5.3 LoD（最少知识）

1. 节点只能调用直接依赖，不得跨层直连孙级节点。
2. 禁止“P4 -> skill”绕过 P5/P6 契约链。

### 5.4 组合复用

1. 优先使用 P5 组合复用，禁止复制半重叠 phase 链。
2. AP 语义复用通过组合关系实现，不通过“语义混合合并”实现。

## 6. 生命周期连续性与 phase 闭合落地规则

1. 单复合流程不得跨非连续生命周期段；跨断点必须拆流程，由上级编排。
2. 每个 phase 必须映射到已定义 P5/P6，且 phase 名称、子流程 ID、I/O 契约三元闭合。
3. 若 phase 无映射、映射冲突或 I/O 不闭合，判定不可执行。

## 7. AP 合并决策树（避免重叠优先；重叠则组合解耦）

```text
输入: AP 候选集合
  |
  +-- 是否存在职责重叠风险?
        |-- 否 --> 可合并为一个 P5 子流程
        |
        |-- 是 --> 是否可通过 profile 隔离语义?
                  |-- 是 --> 保留 AP 语义边界 + 在 P5 组合层编排
                  |
                  |-- 否 --> 禁止合并, 拆分为多个 P5 子流程
```

决策规则：

1. 默认“不合并 AP 语义”优先于“减少流程数量”。
2. 一旦出现重叠，不在 AP 层做语义合并，只能在 P5 组合层解耦。
3. bundle 仅可用于迁移兼容描述，不得成为目标态。

## 8. Fail-Closed 判据与评审检查清单

### 8.1 Fail-Closed 判据

1. 责任重叠存在但未提供解释与解耦策略。
2. 流程拆分违反 MECE、金字塔、单一职责、DIP、LoD 或组合复用任一约束。
3. 生命周期连续性被破坏，或 phase 与 P5/P6 映射不闭合。
4. 设计仍将 bundle 作为目标态运行结构。

### 8.2 评审检查清单

- [ ] 是否给出结论层、分组层、证据层三层表达
- [ ] 是否存在一对多/多对多责任映射且已解释
- [ ] 是否给出 profile 边界或组合解耦策略
- [ ] 是否声明迁移顺序、兼容期与退役状态流
- [ ] 是否满足连续性与 phase 闭合约束
- [ ] 是否明确 bundle 非目标态
